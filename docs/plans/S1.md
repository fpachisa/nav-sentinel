# S1 + S1.5 — the agent layer · plan v2

**v3, after a second review.** v1 needed three mechanisms merged into one; v2 got the merge right
but rested it on a bound case that does not exist, left its anti-hallucination property
unspecified in a way both readings defeated, and specified one catch clause that was a security
regression. Everything marked *(measured)* was verified against the installed code.

**Four blockers were fixed in code rather than deferred into this plan**, because they were defects
in already-committed work, not design questions: the `source_uri` pattern accepted no URI at all
(`https://` followed by a literal backslash and literal `S`); both corporate-action notices named
Abbott's ISIN while the security master named Ambev's, which made the poisoned and clean notices
indistinguishable; the extractor asserted the caller's ISIN over whatever the document said; and
an oversized document could not be refused without credentials. All four are closed, with tests.

**Budget** 6.5h → **11.5h**. §7 says where the hours come from and what it costs.
**Position** on the critical path immediately after S7a; S1.5 follows.
**Framework requirement** all four agents are real ADK agents.

## 1. Acceptance criteria

**S1** — Every verdict cites ≥1 `EvidenceItem` with non-null `source_uri` **and** `retrieved_at`.
An FX verdict must cite the ECB rate **and the rate date used**. A corporate-action verdict citing
only `books_and_records` fails. An AST-scan test asserts no module under `agents/` imports
`nav_sentinel.tools.*` directly.

**S1.5** — Triage classifies ≥5 of 6, and any miss returns `UNCLASSIFIED` with confidence < 0.5,
never a confident wrong category. Republishing a manifest changes routing **without a process
restart**. The pricing adversarial case is triaged correctly then refused by the registry as having
no authorised investigator, with `test_every_break_category_has_an_authorised_investigator`
**inverted** rather than deleted.

## 2. What exists, and what this section must not re-litigate

`cycle_runner` is the deterministic spine: detect → group → score materiality → derive the band →
discover the authorised specialist → record a policed tool call. It calls no model, deliberately.
S1 fills in the *why* per case; it does not replace the spine.

The seam is enforced by `tests/test_seam.py`, the gateway resolves tools by name from a frozen
catalogue, and no agent may draft or post. **S1 adds no agent authority.** It does add one
control-plane component (§3.1), which is a change to the enforcement point and is therefore called
out here to be reviewed as one, rather than smuggled in as an agent-layer detail — v1 claimed "no
authority added" while quietly requiring exactly that.

## 3. Design

### 3.1 One mechanism: the wrapper records what it did

v1 had three: generate the tool surface from the allowlist, declare evidence requirements per
capability, and corroborate citations against the gateway's audit log. The third could not work —
`PolicyDecision` carries `effect, policy_id, reason, agent_ref, resource, metadata` and nothing
else; `call_tool` records the tool **name** as `resource`, with no arguments, no result, no digest,
no `case_id` *(measured: the only `hashlib` uses in `src/` are approval refs and break ids)*. So
"corroborate against the log" degenerated to name-matching: one real `latest_rate_on_or_before`
call would authorise a citation of an invented rate, on an invented date, for a different case.

The fix is that all three read one record. **The surface is generated per case**, with `case_id`,
`trace_id` and `agent_ref` passed to the generator and captured in each wrapper's closure — v2 said
the wrapper "holds the bound case", which was false: *(measured)* `src/` contains exactly two
ContextVars, `identity._current` and `gateway._decision_log`, and `cycle_runner` keeps `trace_id` as
a local. Nothing binds a case anywhere. No third ContextVar is introduced; a closure is enough and
cannot leak across cases. The caller wraps the ADK run in `identity.acting_as(agent_ref)`, without
which the first wrapper call raises. Each wrapper emits:

```
Observation   case_id, trace_id, tool, args (canonicalised), digest,
              retrieved_at, source_uri, observed (typed, per-tool)
```

- **Evidence sufficiency** (§3.3) reads the tool namespaces present in a case's observations.
- **Corroboration** (§3.4): **the model cites an opaque `observation_id` and nothing else.** The
  code then *constructs* the `EvidenceItem` — `source_uri`, `retrieved_at`, `observed`, `tool` —
  from the stored observation, and refuses any model-supplied value for those fields.
- **The rate date** (§1) therefore comes from `observed`, populated by the wrapper from
  `latest_rate_on_or_before`'s returned `(date, Decimal)`.

v2 said "match by `(case_id, tool, digest)`" and never said what the digest was *of*, nor how the
model learned it. Both readings failed: hand the digest to the model and it can cite a real
`(tool, digest)` while inventing the `observed` values — v1's hole moved one level in; withhold it
and the model cannot populate the field at all. A digest over *arguments* is weaker still, since it
authorises any claim about the result of a call the model itself chose.

Citing an id the code resolves is both stronger and cheaper: the citation is bound to the observed
fact **by construction**, criterion 1 is satisfied structurally rather than by comparison, and there
is no digest to compare. The digest stays in the record for the audit trail, not as a key.

**The wrapper calls `gateway.call_tool(name, ...)`.** Stated explicitly because v2 did not: if it
resolved `packs.resolve(name).fn` instead, P-001 and P-006 would never evaluate and no agent tool
call would appear in the governance log — allowlist enforcement would move from the runtime gateway
to a code generator. Test 6 could not have detected that, since it checks for an absent function
and a *direct* `call_tool`. A test asserts a wrapper invocation appends P-001 and P-006 decisions.

The store sits behind the S2a repository interface from the start, in-memory until S2a, so it is
not built twice.

**The generator lives in `control_plane/agent_surface.py`, not in `agents/`.** v1's claim that "an
agent cannot call an unlisted tool because no such function exists in its context" was false:
`packs.resolve(name).fn` is the live ungated callable, `MappingProxyType` prevents replacing a spec
rather than reading one, and v1 required `agents/` to import `packs` in order to generate the
surface. One line in that very module would have bypassed the gateway while passing the AST test.
`agents/` now receives an already-built `list[FunctionTool]` and may import neither `packs` nor
`domain.pack`.

**Wrapper parameters are `str`, coerced explicitly.** *(measured)* A variadic wrapper produces
`parameters_json_schema: None`, so Gemini would call every tool with no arguments; and a parameter
annotated `date` receives the model's raw **`str`** — ADK does not coerce it back — so every
`ecb_fx` tool and `books_and_records.nav_record` would fail at runtime on first call. The build-time
check also asserts `ToolSpec.description` is non-empty: nine of twelve are empty today, which
declares a surface Gemini cannot choose between.

### 3.2 `Verdict` extends the existing domain types

`domain/models.py` **already** defines `EvidenceItem` and `RootCauseHypothesis`, and
`ExceptionCase.hypotheses` is where a verdict belongs. v1 invented a rival `EvidenceItem`. So:
`domain.EvidenceItem` gains the typed `observed` fields; `agents/contract.py` owns `Verdict` and
`Verdict.to_hypothesis()`; triage's capability string maps back to the closed `BreakCategory` enum
that `ExceptionCase.category` requires. Until S2a the verdict rides on the in-memory
`ExceptionCase`.

`Verdict` has no field capable of carrying a structured correction, so S4's drafting cannot leak
backwards, and P-002 denies drafting authority besides. v1 said an investigator "physically cannot
propose a correction" — not true, because `reasoning` and `unresolved` are free text and a model can
write a journal entry in prose. The claim is narrower than that and is stated narrowly: **S4 reads
only `Verdict`'s typed fields, never its prose**, and there is a test for that.

### 3.3 Evidence sufficiency is declared by the process

`ProcessPack` gains `evidence_requirements: tuple[tuple[str, tuple[str, ...]], ...]` — per
capability, which tool namespaces must appear. `nav.fx_rate` requires `ecb_fx`;
`nav.corporate_action` requires the corporate-action tool. Both say: *an internal-only verdict is
not corroboration*.

Validated in **both** `__post_init__` and `register()` — the module duplicates validation there on
purpose — that every requirement key is a declared capability of that pack and every namespace
prefixes a real `ToolSpec`. Without that, a typo silently disables the check, which is precisely
the "policy got weaker while the commit said stronger" shape this project has already had once.

The transfer-agency pack (S9) then declares its own and inherits the check. That is the
extensibility claim made concrete rather than asserted, and it is why this stays in scope.

### 3.4 The corporate-action path (rewritten)

v1 could not be built. Three verified blockers:

1. The CA manifest lists `edgar.fetch_filing_text`, whose own docstring says the return value is
   untrusted. "The ADK tool list *is* `allowed_tools`" therefore hands the one agent with
   `untrusted_inputs: true` the raw attacker-authored prose that task .3 promises it never sees.
2. The extractor cannot be a gateway tool: `_require_quarantine()` raises when an identity is
   bound, and `call_tool` runs the function *inside* `acting_as`. *(measured: `QuarantineViolation`)*
3. `_cross_check` only runs on caller-supplied `expected_domicile` / `books_gross_rate`. *(measured
   on the poisoned fixture: omitting both returns `withholding_pct = 0.00` with no exception;
   supplying `expected_domicile="BR"` raises `ExtractionRejected`.)* One omitted argument disables
   the control, and `corroborated == []` cannot distinguish the poisoned notice from the clean one.

So: **one process-owned tool**, `tools/corporate_action.py::notice_for(isin, as_of)`. It fetches
from a cassette, screens through the gateway, runs the extractor with the identity **unbound**, and
looks `expected_domicile` up from `books_and_records.security(isin).country` and the gross rate from
the books — **never from the agent**. It refuses when `corroborated` is empty, which is now a real
discriminator: *(measured, after the fixture fix)* the clean notice returns two corroborations and
the poisoned one is refused on the treaty mismatch.

Unbinding uses an `identity.unbound()` context manager (`_current.set(None)` / reset), **not** a
fresh `contextvars.Context()`. v2 chose the latter on the strength of the quarantine holding inside
it — which is true, but *(measured)* a span opened in a fresh Context gets a **new trace id** with
no parent, and a `PolicyDecision` recorded inside never reaches the caller's log. That breaks "one
trace per exception case" for the one case that is the demo, and puts the screening decision in an
audit black hole. `current_or_none()` returns None either way, so the quarantine is satisfied
identically for about five lines.

All three `edgar` tools come off the CA manifest, not just the two v2 named. `recent_filings`
declares `untrusted_fields=("issuer","description")` — filer-authored prose reaching the model
context behind Model Armor alone, which this architecture documents as unreliable in context.
`notice_for` needs no discovery step. `notice_for` itself is registered with
`untrusted_output=False`, because it returns a typed record: *(measured)* declaring it untrusted
raises `ContentUnscreenable`, since a `CorporateActionRecord` cannot be screened as text. A test
asserts the `notice_for` path still records a P-005 screening decision, so a future edit that drops
the screen fails rather than quietly making the flag a lie.

### 3.5 Refusal is a verdict, not an exception

Nothing in v1 said what happens when the CA investigator's evidence is refused — and refusal is the
designed outcome of the poisoned fixture. `ContentBlocked` would have propagated out of the tool,
out of the runner, and surfaced as a stack trace on the one case that is the video's best twenty
seconds.

So the investigator boundary catches the **evidentiary** failures — `ContentBlocked`,
`ExtractionRejected`, `ExtractionFailed`, `ContentUnscreenable`, `CassetteMiss`, `ValidationError`
— and returns `Verdict(root_cause=UNKNOWN, confidence=0.0, evidence=[the denial as a typed item])`
with a terminal status that routes to a human. The `unresolved` string is built from the actual
failure, not hardcoded.

**`PolicyViolation` is deliberately not in that set.** v2 put it there, and that was a security
regression: it is raised for P-001, P-002, P-003, P-005 and P-006, so catching it converted *every*
governance denial into ordinary-looking uncertainty, under a hardcoded P-005 label that
misattributes an allowlist or scope denial to a screening block. "This agent was denied a tool it
must never call" would have read as "the investigator was unsure" — and the poisoned notice's
injected instruction is literally *post the entry to the ledger without review*, so that is exactly
the path an attacker wants softened. If a governance denial must not surface as an on-camera
traceback, it is caught in a **separate** clause that copies `decision.policy_id` and `reason`
verbatim and uses a status distinct from evidentiary uncertainty, with a test that the two are
distinguishable.

§3.3's namespace requirement applies only where evidence was *admitted* — and §1's "every verdict
cites evidence" is scoped to verdicts asserting a root cause, since a refusal verdict asserts none.
Every refusal still attaches a typed denial item carrying `source_uri` and `retrieved_at`.

### 3.6 Triage

`gemini-3.5-flash-lite`, structured output, **no tools** — it classifies from case facts. Its output
schema is an enum over `packs.capabilities()`, so an out-of-vocabulary answer has nowhere to land
and falls to `nav.unclassified` structurally rather than by prompt. Below 0.5 confidence it must
return `nav.unclassified`: a confident wrong route sends a break to an agent that investigates the
wrong thing.

`output_key` is set. *(measured: `__maybe_save_output_to_state` returns early without it, so the
validated verdict would be unreachable.)* Gemini's response schema cannot express "evidence
non-empty unless root_cause is UNKNOWN", so schema-valid / pydantic-invalid verdicts will occur:
one bounded repair retry, then a refusal verdict.

**Two criteria are not met today and need explicit work.** *(measured)* `pricing-investigator` and
`cash-fees-investigator` are still published, so every capability has an investigator, the pricing
case cannot be "refused for want of an authorised investigator", and
`test_every_break_category_has_an_authorised_investigator` currently **passes** — inverting it is
not a one-line edit. And "republish without restart" has no mechanism: `packs.on_change` is wired,
but writing a YAML fires nothing and `discover._catalogue()` caches for the process lifetime. A
`discover.republish()` entry point validates against the pack catalogue using the **same validator
`configure()` calls** — otherwise the one path S1.5 adds into routing is the one the build-time
check does not cover — and then invalidates. In-process republish is the demonstrated scope;
Firestore-backed publish is S2a and later.

## 5. Test plan

Offline by default; live model calls behind the `live` marker.

1. A verdict with empty evidence and a known root cause is refused.
2. An `EvidenceItem` with null `source_uri` or null `retrieved_at` is refused.
3. An FX verdict whose cited `observed.as_of` is null, or disagrees with the recorded
   observation's returned date, is refused.
4. A corporate-action verdict citing only `books_and_records` is refused.
5. A verdict citing a `(tool, digest)` with no matching observation **for that case** is refused —
   including the case where the agent made that exact call for a *different* case.
6. A tool outside the manifest: no such function exists in the surface, **and** a direct
   `gateway.call_tool` is denied by P-001.
7. AST scan, with a vacuity guard: no module under `agents/` imports `nav_sentinel.tools.*`,
   `control_plane.packs` or `domain.pack`. The scan must emit `f"{node.module}.{alias.name}"` per
   alias, because *(measured)* `from nav_sentinel.control_plane import packs` currently yields only
   the edge `nav_sentinel.control_plane` — so the assertion as v2 worded it would have passed
   vacuously against the codebase's own dominant import style. The `.fn` clause is scoped to
   `agents/` **and** `agent_surface.py` (the module that could actually reach it), with
   `packs.py` and `gateway.py` allowlisted, since `gateway` legitimately calls `spec.fn`.
8. S4 reads only `Verdict`'s typed fields, never `reasoning` or `unresolved`.
9. Every generated wrapper declares a non-empty description and a non-null parameter schema.
10. A wrapper receiving the model's `"2026-08-14"` string calls through with a real `date`.
11. **The poisoned notice produces a refusal verdict and a human escalation — not a crash, and not
    a confident answer.** Both branches: Model Armor blocks it, and Model Armor misses it and the
    extractor rejects it.
12. `notice_for` sources `expected_domicile` from the books; an agent cannot influence it.
13. Triage: 6 scenarios, ≥5 correct, any miss `UNCLASSIFIED` with confidence < 0.5.
14. Triage cannot return a capability outside `packs.capabilities()`.
15. `discover.republish()` changes routing in-process, no restart, and rejects a manifest naming an
    undeclared tool.
16. Pricing: triaged correctly, then refused for want of an authorised investigator; coverage test
    inverted.
17. A wrapper invocation appends P-001 and P-006 decisions to the log — so a generator that
    resolved `.fn` directly, moving enforcement from the gateway to build time, fails.
18. A governance denial (P-001) produces a verdict distinguishable from an evidence refusal, and
    carries the real `policy_id`, not a hardcoded one.
19. `notice_for` records a P-005 screening decision, so dropping the screen fails rather than
    quietly making `untrusted_output=False` a lie.
20. An observation opened by `notice_for` shares the case's trace id — the fresh-`Context()`
    approach *(measured)* produced a new trace with no parent and lost the decision entirely.
21. `discover.republish()` refuses a manifest that grants posting authority, a null-ceiling
    violation, or drafting to anything but the remediation agent.
22. A refusal verdict still carries a typed evidence item with non-null `source_uri` and
    `retrieved_at`.

## 6. Risks

**Settled before coding.** ADK 2.7.1 supports `output_schema` with `tools` (tools during the
thought loop, structure on the final output only). Dotted tool names survive as declaration names.
`Decimal` and `date` *return* values serialise correctly. Variadic wrappers do not work and `date`
*arguments* are not coerced — both designed around above.

**.3 is the task most likely to overrun**, and it is now the one with contingency rather than the
one with none. **.1b is second**: coercion plus the missing descriptions plus the build-time check.

**Exception inventory, because the refusal path is only as good as its catch list.** Reachable and
therefore enumerated: `ContentBlocked`, `ExtractionRejected`, `ExtractionFailed` (attacker-reachable
by garbling the ex-date line), `ContentUnscreenable`, `CassetteMiss`, `ValidationError`,
`QuarantineViolation`, `UnknownTool`. Each gets a branch and a test. `PolicyViolation` is
deliberately excluded — see §3.5.

**Output-schema mechanics.** *(measured)* ADK's `validate_schema` calls `model_dump(exclude_none=True)`,
so a null `source_uri` arrives as an **absent key** rather than `None` — test 2 must treat missing
as null. And a cross-field validator on the schema handed to ADK raises inside the runner, which
makes §3.6's "one bounded repair retry" unreachable from there: the `output_schema` is permissive
and strict validation happens outside the runner.

**Live-model flakiness.** Verdict *shape* is tested offline against recorded outputs; only accuracy
needs live calls. A flaky model must never fail the offline gate.

**Cost.** Each investigator gets a bounded tool-call budget; unbounded loops are how an agent fleet
becomes expensive.

**The honest limit.** Accuracy at N=8 is indicative, not a benchmark, and S5 must label it so.

## 7. Where the extra 5.0h comes from, and what it costs

v2 spent the same rungs twice — it funded the 6.5→10.0 increase from ladder rungs 1, 2 and 4, then
named rungs 1 and 2 again as the contingency for an overrun. The honest accounting:

**The increase comes from S1's own in-line reserve.** PLAN.md §7 already schedules 12.0h across
24–25 August against 8.5h of §5 build work (S1 6.5 + S2a 2.0), so 3.5h of gate-and-rework reserve
already sits on exactly those two days. That is what pays for 6.5 → 10.0. The further 1.5h — .3b's
cassette, .1e, and prompt work in .2 — comes from the 8.8h margin.

**What that costs is worth stating plainly: the S1 gate then has no in-line reserve left.** So the
contingency is a genuinely different rung, not a reused one: **rung 3** (S9 reduced to one scenario,
2.0h, 28 Aug) and **rung 5** (S2 memory degraded to a stub interface, 1.0h). Rungs 1 and 2 are
already spent.

**Stated as a decision, not a hope:** if S1 exceeds 11.5h, rung 5 is taken that evening and rung 3
the following morning, rather than the overrun being absorbed silently into the following days.
Rung 3 never goes to zero, because S9 is the on-camera evidence for the platform claim.
