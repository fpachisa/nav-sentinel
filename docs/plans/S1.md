# S1 + S1.5 — the agent layer · plan for review

**Budget** 6.5h: S1.1 contract 2.0 · FX investigator 1.5 · corporate actions 2.0 · triage 1.0.
**Position** S1.1 is on the critical path immediately after S7a; S1.5 follows it.
**Framework requirement** all four agents are real ADK agents. S0a's throwaway probe does not count.

## 1. Acceptance criteria (from PLAN.md §6, restated so this plan can be checked against them)

**S1** — Every verdict cites ≥1 `EvidenceItem` with non-null `source_uri` **and** `retrieved_at`.
An FX verdict must cite the ECB rate **and the rate date used**. A corporate-action verdict citing
only `books_and_records` fails. An AST-scan test asserts no module under `agents/` imports
`nav_sentinel.tools.*` directly.

**S1.5** — Triage classifies ≥5 of 6 scenarios, and any miss returns `UNCLASSIFIED` with confidence
< 0.5, never a confident wrong category. Republishing a manifest changes routing **without a
process restart**. The pricing adversarial case is triaged correctly and then refused by the
registry as having no authorised investigator, and
`test_every_break_category_has_an_authorised_investigator` is **inverted** to assert exactly that
gap rather than deleted.

## 2. What already exists, and what this section must not re-litigate

`cycle_runner` is the deterministic spine: detect → group → score materiality → derive the band in
the control plane → discover the authorised specialist → record a policed tool call. It calls no
model, deliberately. S1 does **not** replace it; it fills in the *why* for each case.

Today every case comes back `nav.unclassified` because nothing classifies. That is the gap S1.5
closes, and it is why the current demo shows seven cases all escalating.

The seam is already enforced (`tests/test_seam.py`), the gateway resolves tools by name from a
frozen catalogue, and no agent may draft or post. **S1 adds no authority.** Any design below that
would need an authority change is wrong by construction.

## 3. Design

### 3.1 The tool surface *is* the allowlist (S1.1)

Each investigator's ADK `tools=[...]` list is **generated from its manifest's `allowed_tools`**, and
every generated tool is a thin wrapper that calls `gateway.call_tool(name, ...)`. Nothing else is
importable from `agents/`.

This makes P-001 structural as well as policed: an agent cannot call an unlisted tool because no
such function exists in its context, *and* the gateway would deny it if one did. Belt and braces,
in that order — the gateway stays the enforcement point, the generated surface just removes the
temptation.

Build-time check: if a manifest lists a tool the process pack does not declare, `configure()`
fails. A manifest naming a nonexistent tool is a deployment defect, not a runtime surprise.

### 3.2 `Verdict` is the only thing an investigator can return

```
EvidenceItem   tool, source_uri (non-null), retrieved_at (non-null), digest, summary, trusted
Verdict        case_id, capability, root_cause, confidence, evidence[], reasoning, unresolved
```

There is **no remediation field**. An investigator physically cannot propose a correction, which
is P-002 expressed in the type system rather than only in a policy check. Drafting is S4's
remediation agent.

Validated at the boundary with pydantic: `confidence` in [0,1]; `evidence` non-empty whenever
`root_cause` is not `UNKNOWN`; every item's `source_uri` and `retrieved_at` non-null.

### 3.3 Evidence sufficiency is declared by the process, not chosen by the agent

The acceptance criteria say an FX verdict must cite the ECB rate *and the rate date*, and that a
corporate-action verdict citing only `books_and_records` fails. Hard-coding those two rules inside
two agents would make them invisible and unextendable — and this project's headline claim is that a
new process plugs in without touching the control plane.

So `ProcessPack` gains a per-capability **evidence requirement**: which tool namespaces must appear
in a verdict's citations for it to count as corroborated. `nav.fx_rate` requires `ecb_fx`;
`nav.corporate_action` requires `edgar`. Both requirements say, in effect, *an internal-only
verdict is not evidence* — the agent must have corroborated against external truth.

Checked in the control plane, once, for every capability. The transfer-agency pack (S9) then
declares its own requirement and inherits the check for free, which is the extensibility claim made
concrete rather than asserted.

### 3.4 Citations are corroborated against the audit log

A verdict's `evidence` must correspond to tool calls the gateway **actually recorded** on that
case's trace. An investigator that cites an ECB rate it never fetched is rejected.

This is the anti-hallucination control, and it is cheap because the gateway already logs every call
with a result digest. Without it, "every verdict cites evidence" only proves the model produced
well-shaped citations — which a model will happily do for a rate it invented.

### 3.5 Triage (S1.5)

`gemini-3.5-flash-lite`, structured output, **no tools** — it classifies from the case facts, it
does not investigate. Returns `capability` + `confidence`. Below 0.5 it must return
`nav.unclassified`; a confident wrong category is the failure mode that matters, because a wrong
confident route sends a break to an agent that will investigate the wrong thing.

Routing stays with the registry: triage names a capability, `discover.discover_for_capability`
decides who may handle it, and a capability with no authorised investigator escalates to a human.
The pricing case exercises exactly that path.

Hot republish: the registry cache must invalidate on manifest change — `packs.on_change` exists for
this. Test by republishing a manifest in-process and asserting the route changes with no restart.

## 5. Test plan

Offline by default; live model calls behind the `live` marker, as everywhere else.

1. A verdict with empty evidence and a known root cause is **refused**.
2. An `EvidenceItem` with null `source_uri` or null `retrieved_at` is **refused**.
3. An FX verdict citing the rate but **not the rate date** is refused.
4. A corporate-action verdict citing only `books_and_records` is refused; adding `edgar` passes.
5. A verdict citing a tool call that **never appears in the audit log** is refused.
6. An investigator asked for a tool outside its manifest: the function is absent, *and* a direct
   `gateway.call_tool` for it is denied by P-001.
7. AST scan: no module under `agents/` imports `nav_sentinel.tools.*`.
8. `Verdict` has no field that could carry a proposed correction (guards against S4 leaking back).
9. Triage: 6 scenarios, ≥5 correct, any miss is `UNCLASSIFIED` with confidence < 0.5.
10. Republishing a manifest changes routing in-process, no restart.
11. Pricing case: triaged correctly, then refused for want of an authorised investigator — and
    `test_every_break_category_has_an_authorised_investigator` inverted to assert that gap.
12. A manifest listing a tool the pack does not declare fails `configure()`.

## 6. Risks

**Resolved before planning.** ADK 2.7.1 supports `output_schema` together with `tools` — verified in
`llm_agent.py`: tools are exposed during the thought loop and structure is enforced on the final
output only. This was the one unknown that would have changed the design.

**Live-model flakiness.** Verdict *shape* is tested offline against recorded model outputs; only
accuracy needs live calls. A flaky model must never be able to fail the offline gate.

**Cost and latency.** Each investigator gets a bounded tool-call budget. Unbounded loops are the
predictable way an agent fleet becomes expensive.

**The honest limit.** Accuracy at N=8 cases is indicative, not a benchmark, and S5 must label it
that way. Overstating it is the mistake this project has already had to correct three times in the
README.
